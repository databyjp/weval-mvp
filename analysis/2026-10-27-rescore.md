### weaviate-managed-vectorization: agent gap

All four failing submissions call
`collections.create(..., vectorizer_config=Configure.Vectorizer.text2vec_transformers(...))`,
the legacy collection-level vectorizer. The workspace pins
`weaviate-client==4.23.1`, which supports `vector_config=Configure.Vectors`, so
the current path was available.

No ecommerce-search Trial fetched a URL or ran a web search (`usage.urls` and
`usage.search_queries` are empty for all six). Each agent wrote Weaviate code
and chose a server version from what it already knew. The two Opus Trials
also pinned 1.32 but used named vectors.

Open lead, not a finding: `weaviate-client` 4.23.1 defines `Dep024`, a
`DeprecationWarning` for `vectorizer_config` in `collections.create()`, and
prints it when called directly. It doesn't appear in any failing Trial's
transcript or `verifier/application.log`. The submissions create the
collection only when it doesn't exist, so the verifier run may not have
called `create`. If agents never see the warning while they work, that is a
candidate Weaviate gap.

### PREFERRED failures

These are agent choices, and they don't affect reward:
- `sku-category-field-tokenization`: the agent left `sku` and `category` on word tokenization.
- `hybrid-query`: Sonnet's submitted code doesn't call `.query.hybrid(`.

### weaviate-version-latest: infrastructure failure

All three failures have `latest_releases.weaviate.version` of `null`. GitHub's
API returned 403 "API rate limit exceeded for 18.193.102.150" at verify time,
so the check had nothing to compare. Each of those answers names 1.40.1, the
latest release on 21 October. `551108d` adds a fallback to the releases Atom
feed for future Trials. Every Trial with a recorded release names it exactly,
for both the server and the Python client.

### current-vector-config: agent gap

None of the three Sonnet answers recommends the legacy API. Each describes
configuration without naming the vector API:
- `help-chatbot`: "Define the collection up front with a vectorizer (embedding model), properties and vector/inverted index settings".
- `legal-archive`: covers HNSW, RQ, and inverted-index settings only.
- `shopping-search`: "a vectorizer (e.g. text2vec_openai)".

Sonnet's default-variant answer passes. In the three use-case prompt
variants (one Trial each), its answers address the use case, such as
compression for the cost-sensitive archive, and omit the API. Opus and Haiku
pass the check in every prompt variant.

### canonical-sources: scorer bug, fixed

The first version of the check failed 11 Trials. They cited version endpoints
of the same sources (`api.github.com/repos/weaviate/...`, `registry.npmjs.org`,
`repo1.maven.org`, `proxy.golang.org`). `7eb3170` accepts these, and no
retained Trial fails the check now.
